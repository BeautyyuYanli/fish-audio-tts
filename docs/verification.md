# Verification

Version 1.0.6 uses internal version code 8 so the Opus build can upgrade installations with the existing version codes 6 and 7. Its synthesis implementation was verified locally on 2026-10-20 with frontend/Android builds, Ogg Opus parser unit tests and integration checks on an isolated Android emulator. The transport is now 32 kbps Opus at 48 kHz, progressively decoded to PCM16 by Android MediaCodec. Local HTTPS fixtures verify the actual decoder, precise pre-skip/end trimming, audio before download completion, cancellation and consecutive utterances. Existing configuration, preview, prefix, Drama 3 and default-voice checks also pass. No valid Fish credential was used, so the opt-in live test was skipped. The earlier live Fish results below used version 1.0.1 and WAV transport; they do not verify the new Opus transport. Physical-device audible playback remains unverified.

`LiveSynthesisTest` is opt-in and skipped by a normal `npm run android:device-test` run. The earlier live check used `-Pandroid.testInstrumentationRunnerArguments.fishCredentialPort=<forwarded-local-port>` and a one-shot host loopback socket supplying a length-prefixed JSON object with `apiKey` and `referenceId` through `adb reverse`. Only the port was passed in arguments; no credential appeared in Gradle arguments or environment variables. Use a dedicated test emulator.

Unit checks parse actual FFmpeg-generated Ogg Opus with three-byte reads, verify progressive consumption, packet durations and final granule positions, and exercise cross-page packet continuation. They reject checksum corruption, truncated headers/bodies, missing end pages, trailing/chained streams, stereo/unsupported mapping, page identity/sequence/continuation errors, invalid granules/durations and oversized packets. Cancellation and network timeouts propagate without being reclassified as malformed audio.

`FishSynthesizerTest` runs on Android because its protocol checks now exercise the real platform Opus decoder. A local MockWebServer uses HTTPS with an ephemeral test certificate trusted only by the injected test client; production cleartext restrictions remain enabled. The HTTP chunk-boundary test selects HTTP/1.1 so chunk framing is handled by the transport. Checks cover the documented Opus request, default/explicit bitrate, profile/model routing, generation precedence, prefix composition, omission of optional fields, HTTP errors, missing configuration, timeout, callback buffer limits/thread ownership, rejected output and cancellation before/during synthesis. Both 20 ms and one-second Ogg pages decode to exactly 195,552 PCM bytes for the 2.037-second fixture, with non-silent output. A fixture with pre-skip extended across multiple packets produces exactly 192,176 bytes; successive utterances reuse the synthesizer successfully. A response throttled after 8,192 of its 11,259 encoded bytes delivers PCM within two seconds, before the next five-second network window, and cancellation finishes on the synthesis thread. This verifies progressive decoding rather than full-response buffering. These tests do not verify Fish authentication, model access, upstream Opus framing, latency or speech quality.

Regenerate the encoded test assets with `sh tools/generate-audio-fixtures.sh` (requires FFmpeg with libopus). The script creates the same 2.037-second sine signal with one-packet and batched Ogg pages in `android/app/src/test/resources`; those resources are shared with instrumentation test assets and are excluded from the application APK. Do not edit the generated `.opus` files manually.

Android checks use the actual package manager, TTS service/binder/client, Keystore, Activity and WebView. They verify exported engine/data handlers; independent key/profile saves; deletion of the key while retaining profiles; discovery and selection of 26 network Voices from two profiles without launching an Activity; and a terminal system synthesis error when no configuration exists. The Vue/bridge check exercises both forms, preserves an unsaved voice draft while saving the key, and adds, edits, removes and reloads list items. Profile IDs survive edits. The key is absent from the reloaded field and browser storage. Tests preserve any original readable configuration while running, but Android's connected-test tooling can uninstall the target package afterwards; use a dedicated emulator for these tests.

Default-voice checks verify selection by profile identity even when references match, encrypted persistence across key/list saves, preservation through profile reordering and key deletion, rejection of missing profile IDs, and fallback after deleting the default or clearing the list. An actual `TextToSpeech` client without an explicit voice selects the saved default; `setLanguage` also uses it, while explicit `setVoice` takes priority. The panel test saves Drama 3 and prefix text, changes the global default without discarding either unsaved edit, then recreates the Activity and verifies all settings reload. The protocol fixture verifies that an accepted Drama 3 profile sends the exact `model: drama-3` header; it is not a real upstream synthesis test.

Prefix fixtures verify exact `prefixText + systemText` request bodies, preservation of leading/trailing whitespace and newlines, a full 4,000-unit system text without truncation, empty prefixes in older configurations, and independent prefixes for selected profiles. The Android panel check verifies that prefix whitespace survives encrypted storage and Activity recreation. The preview's native code applies speed through Android's `setSpeechRate`; the unit request checks separately verify percent-to-multiplier conversion. ## Observed system and network behavior

The debug APK was installed normally using `adb install -r`. Android Settings' **Preferred engine** list contained **Fish Audio TTS**. Selecting it through the ordinary Android confirmation dialog changed `tts_default_synth` to `com.fishaudio.tts`.

`dumpsys activity services com.fishaudio.tts` showed the framework bound to `FishTtsService`, while `dumpsys activity activities` contained no `MainActivity`. This was checked after a fresh installation before opening the panel. With no configuration, Settings' sample playback control remained disabled.

A deliberately invalid test key and the public Reference ID from Fish's official quickstart were then saved through the actual panel. After closing the panel and reopening system Settings, its sample playback control was enabled. A sample request returned a synthesis error to the separate Settings application; `MainActivity` remained absent. This demonstrates the native service/error path and local data-readiness protocol, not successful speech playback.

An earlier authenticated HTTPS POST to `https://api.fish.audio/v1/tts` in version 1.0.1 returned HTTP 200 and `audio/wav`: 42,256 bytes containing non-silent PCM16 mono 24,000 Hz audio. The live Android system test completed synthesis to a file. That result established the engine's HTTPS/system-client path with WAV; it does not establish compatibility of the current Opus reader with actual Fish responses. The WAV reader and its streaming-length handling have been replaced by the Ogg Opus reader.

The Vite production preview was started at `http://127.0.0.1:4173/` and registered using Lody's `lody_report_preview_candidate` tool. In Lody, use the **Browser** button above the message input to open it. Browser previews cannot synthesize or persist credentials.
