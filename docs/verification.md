# Verification

Version 1.0.3 was verified locally on 2026-10-20 with frontend/Android builds, protocol unit tests and integration checks on an isolated Android emulator. These checks cover per-voice prefix text, preview speed controls, disabled pitch, Drama 3 configuration and the saved default system voice. No valid Fish credential was used for this version, so its opt-in live test was skipped and real upstream synthesis with the new prefix/preview controls remains unverified. The earlier live Fish HTTPS and Android synthesis-to-file results below were obtained with version 1.0.1. Physical-device audible playback remains unverified.

## Observed system and network behavior

The debug APK was installed normally using `adb install -r`. Android Settings' **Preferred engine** list contained **Fish Audio TTS**. Selecting it through the ordinary Android confirmation dialog changed `tts_default_synth` to `com.fishaudio.tts`.

`dumpsys activity services com.fishaudio.tts` showed the framework bound to `FishTtsService`, while `dumpsys activity activities` contained no `MainActivity`. This was checked after a fresh installation before opening the panel. With no configuration, Settings' sample playback control remained disabled.

A deliberately invalid test key and the public Reference ID from Fish's official quickstart were then saved through the actual panel. After closing the panel and reopening system Settings, its sample playback control was enabled. A sample request returned a synthesis error to the separate Settings application; `MainActivity` remained absent. This demonstrates the native service/error path and local data-readiness protocol, not successful speech playback.

A real authenticated HTTPS POST to `https://api.fish.audio/v1/tts` using the supplied reference and the upstream model default returned HTTP 200 and `audio/wav`. The response contained 42,256 bytes: a PCM16 mono 24,000 Hz WAV header and 42,212 non-silent PCM bytes. Fish used RIFF length `0xffffff24` and data length `0xffffff00` as streaming placeholders. Version 1.0 treated that data length as an oversized finite file and rejected otherwise valid audio. Version 1.0.1 accepts this paired marker while still limiting bytes actually received. The compiled Kotlin reader extracted PCM exactly matching the captured response payload, and the live Android system test independently completed real HTTPS synthesis to a file with the corrected parser.

The Vite production preview was started at `http://127.0.0.1:4173/` and registered using Lody's `lody_report_preview_candidate` tool. In Lody, use the **Browser** button above the message input to open it. Browser previews cannot synthesize or persist credentials.

Check `speak` and `synthesizeToFile`, profile/language/Voice selection, system-over-table parameter precedence, rate changes and upstream rejection of unsupported rates, stop while waiting and while playing, network loss, background use, and a cold start after reboot and unlock.
