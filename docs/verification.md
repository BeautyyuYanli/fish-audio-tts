## Observed system and network behavior

The Settings and live synthesis observations in this section are historical version-1.0.1 evidence. The current version's actual native service/client and catalog checks are described above.

The debug APK was installed normally using `adb install -r`. Android Settings' **Preferred engine** list contained **Fish Audio TTS**. Selecting it through the ordinary Android confirmation dialog changed `tts_default_synth` to `com.fishaudio.tts`.

`dumpsys activity services com.fishaudio.tts` showed the framework bound to `FishTtsService`, while `dumpsys activity activities` contained no `MainActivity`. This was checked after a fresh installation before opening the panel. With no configuration, Settings' sample playback control remained disabled.

A deliberately invalid test key and the public Reference ID from Fish's official quickstart were then saved through the actual panel. After closing the panel and reopening system Settings, its sample playback control was enabled. A sample request returned a synthesis error to the separate Settings application; `MainActivity` remained absent. This demonstrates the native service/error path and local data-readiness protocol, not successful speech playback.

An earlier authenticated HTTPS POST to `https://api.fish.audio/v1/tts` in version 1.0.1 returned HTTP 200 and `audio/wav`: 42,256 bytes containing non-silent PCM16 mono 24,000 Hz audio. Its live Android system test completed synthesis to a file. That result established the older WAV path. The WAV reader has now been replaced by the Ogg Opus reader; current transport evidence is reported separately above.

The Vite production preview was started at `http://127.0.0.1:4173/` and registered using Lody's `lody_report_preview_candidate` tool. In Lody, use the **Browser** button above the message input to open it. Browser previews cannot synthesize or persist credentials.
